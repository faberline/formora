## 目標與依賴
為 #3 實作真正的 Rust 基本形狀生成。接續 #32 / PR #33 的多邊形資產，先建立共用的生成、參數保存與重建流程。這批涵蓋平面、方塊、格線及圓；其餘基本形狀仍在完整路線圖內。PR #33 未通過三平台 CI 前，不整合其依賴變更，也不宣告任何 milestone 完成。

## 交付內容
- Rust 根據參數產生頂點、邊、有方向多邊形、法線及預設 UV。執行檔不得讀取 baseline/reference、測試資料、Blender 或 Python 來產生幾何。
- CLI 與 MCP 共用建立及重建指令。保存已解析的參數與是否經手動修改。相同參數須產生相同 ID 與幾何。
- 建立不覆寫既有資產。重建明確替換既有資產的幾何與屬性，保留資產 ID 與實體引用。局部改點標記為已編輯。可用保存參數重建，也可明確提供新參數。
- 加入明確的生成資源預算。先估算頂點、邊、面及面角總數，檢查算術與預算後才分配。預設總數上限 1,000,000，呼叫者可指定預算。超限明確失敗，不默默減少細分。

## 固定品質條件（實作前）
- 既有 mesh-primitives suite 中這四種形狀的 20 組輸入，由實際 Rust 指令生成，經 CLI 及官方 MCP 呼叫並儲存重開。使用未降低的既定比較器：頂點與有方向拓撲、邊、逐面角 UV／法線、平滑旗標、變換及邊界；數值上限維持 1e-6。
- 實作平面／格線尺寸 0、方塊尺寸 0、圓半徑 0 的既有上游邊界行為。方塊尺寸 0 對應上游的單位方塊；平面／格線的退化頂點不合併。
- 零半徑填面圓的來源 UV 未定義。沿用原有規則：只替代未定義分量為有限 0，回傳並保存 degenerate_default_uv 診斷。不得把未定義值記為數值零誤差。全部有限 UV 仍遵守原誤差上限。
- 上述邊界來源來自 context suite。本 issue 的附加子檢查只驗證幾何、UV、法線與變換；不複製未實作的選取／來源標記以假裝通過完整 context case。完整共用選項、插入及選取驗收保持未執行。
- 接受官方已記錄的參數型別及數值範圍。錯誤參數、非有限值、重複 ID、預算超限及算術溢位須原子失敗。完整上界幾何精度與容量驗收仍待追加上游案例，不能僅憑本批有限案例宣告功能對齊。

## 固定驗證與效能條件
- 測試建立、重建、手動改點、共享引用、儲存重開、undo、失敗回復及命令 schema。移走 baseline/reference 的獨立程序仍須正常生成。
- macOS Metal 實際渲染由 Rust 生成的四種形狀，修改參數後圖像可見改變；重開一致。
- Apple M1 Max / macOS / release，三次測量：100×100 細分格線與 4,096 點填面圓。各次純生成 <= 500 ms，建立／改參數重建／儲存／重讀合計 <= 2 s。既有兩個資產效能樣本與上限保留。
- Rust 1.85 的格式、Clippy、完整 Rust 測試、Python 比較器測試、官方 MCP 與現有三平台 CI 必須通過。未啟動或未執行的必要檢查不得視為通過。
- 合併後核對實作候選與整合內容，再由 Codex 獨立驗收。
