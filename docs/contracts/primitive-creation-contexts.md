# Primitive creation and insertion contract

## 目標與依賴
接續 #42 / PR #43 與 #40 / PR #41，實作共用的場景物件建立及網格插入流程。屬於 #3。使用 Rust 核心，CLI 與 MCP 共用同一操作。依賴鏈的三平台 CI、整合與獨立驗收條件不變。

## 固定功能條件（實作前）
- 保存可查詢的建立環境：游標位置、游標旋轉與視角旋轉。支援世界、游標、視角對齊與明確覆寫位置／旋轉。
- 以十種既有 Primitive 參數建立場景網格物件，或加入指定既有網格實體的共享資產。明確指定資產、實體及新增元件 ID 前綴。不得覆寫既有 ID 或焊接位置重合的頂點。
- 插入須使用目標實體的世界變換計算資產本地座標。支援父階層。既有實體、共享引用、材質、群組、接縫及無關屬性保持正確；奇異目標變換須原子拒絕。
- 依固定上游行為處理 UV 第一層初始化、既有層順序、目前使用的層與新增面角資料。保留既有 UV。Torus 的插入、材質及對齊規則依固定 Python 來源，不用其他形狀的規則替代。
- 保存目前材質索引。插入後依來源選取新增元件，取消既有元件選取。保存可查詢的選取旗標，並讓成果預覽可選擇顯示元件標記。
- 不要求舊式 GUI 模式。產品須實際支援新建後編輯與既有網格插入。每個案例都要執行修改及復原來證明能力，不能從來源複製模式或選取答案。
- 回傳每個建立／插入命令的實際新增元件 ID 收據；只在整批成功儲存後回傳。來源歸屬由收據與實際前後查詢計算，不從預期結果或命名猜測。
- 保存配方的建立座標框架，重建保留同一局部座標意義及實體引用。插入標記既有配方已編輯。儲存、重開及 undo 必須保持結果。

## 固定品質與驗證條件
- 使用原有 mesh-creation-contexts 全部 131 組：91 組新物件、40 組既有網格插入。CLI 與官方 MCP 各執行全部案例，共 262 組。
- 保持原有比較器與 1e-6 限值。完整比較有向拓撲、位置、面／面角法線、平滑、UV 層順序與目前層、材質、選取及既有／新增元件歸屬。不能只比較數量。
- 初始資料只來自已固定的作者輸入與 seed fixture。執行檔不得讀取參考輸出、Blender 或 Python；不得向 Rust 傳送預期的新增幾何、選取或歸屬答案。
- 零半徑填面 Circle 的未定義 UV 沿用有限零值、明確診斷與 null 數值誤差規則。其他有限值的限制保持不變。
- 所有失敗（無效參數、無效引用、重複 ID、奇異矩陣、非有限變換、預算不足、stale revision、批次中途失敗、寫檔失敗）須保持檔案、記憶體與 undo 歷史。
- 保留所有既有測試：162 組生成、八組額外縮放、1060 組選取、57 組 payload、官方 MCP，以及全部 Rust/Python 測試。使用真正 Rust 1.85 的固定絕對子工具路徑。
- 新增有意義的父階層、共享引用、legacy triangle 身分、命名前綴衝突、UV 與材質保持、選取歷史、配方重建、重開與回復測試。

## 固定效能與成果條件
- Apple M1 Max / macOS / release，新建 100×100 grid 與向 seed cube 插入 100×100 grid 各量測三次。新建／插入核心 <=500 ms；完整操作、儲存及重讀 <=2000 ms。保留原有效能案例與門檻。先檢查新增及合併後元件預算，再配置幾何。
- Metal 實際顯示游標／視角對齊物件及既有網格插入結果。修改後有可見變化；儲存重開圖片完全一致。收據及查詢須能定位新增部分；元件標記不得改變表面點選。
- 保留固定輸入、來源版本、Rust／shader／工具、執行檔、收據、前後查詢、時間與圖片雜湊。隔離程序禁止讀取原始碼庫後仍須能建立及插入未見過的輸入。
- 必要三平台 CI、依賴整合與整合後的 Codex 獨立驗收通過前，issue 保持開啟。未執行或失敗的必要測試都不是通過。

## 剩餘範圍
完整數值上界與容量、其他物件型別／模式切換、參數預設管理、一般建模、原生視窗輸入與 Windows/Linux GPU 驗收仍在完整路線圖內。有限案例不代表完整功能或任何 milestone 完成。
