# Agent 操作精度

本文件說明現有操作的精度邊界。
它不改動算子、儲存格式、來源資料或驗收門檻。
操作欄位仍以 `formora scene schema` 或 MCP `tools/list` 為準。

## 資料精度與算子精度

`f64` 是 64 位元浮點數。`f32` 是 32 位元浮點數。
兩者都可能有捨入。f32 能保留的有效位數較少。

場景的 `Transform.precision` 控制一般變換的求值路徑。
預設是 `f64`，所以儲存時可以省略此欄位。
此欄位不是所有算子的全域精度開關。
某些著錄旋轉表示也依固定來源的 f32 演算法求值。

| 路徑 | 現有行為 |
|---|---|
| 原生場景儲存與重開 | 有限 f64 欄位使用精確浮點往返讀取，保留已保存的值 |
| `set_mesh_asset`、`set_mesh_vertices` | 保存請求提供的有限 f64 頂點；不經 snap 的 f32 運算 |
| `set_transform` | 保存提供的變換欄位；實際求值仍取決於精度欄位及旋轉表示 |
| 原語建立與重建 | 幾何依固定來源的 f32 算術產生；存入 f64 欄位不會恢復已捨入的位數 |
| `snap_scene`、`snap_mesh` | 依各自固定合約執行來源相容 f32 運算 |
| 原生 GPU 預覽 | 使用 f32 繪圖資料；影像不能代替原生 f64 幾何核對 |

來源相容 snap 的規則見[場景 snap 合約](contracts/scene-snap-core.md)及
[旋轉 snap 合約](contracts/snap-rotation-core.md)。
變換精度與 delta 的分工見[delta 合約](contracts/snap-delta-core.md)。

## 只改原點的 snap

`set_object_context` 的 `origins_only` 可與 `snap_scene` 配合。
它會補償受影響網格的局部座標。
`skip_children` 也可能寫入子物件的父反向矩陣。

此路徑仍使用來源相容的 f32 算術。
即使物件是 `precision: f64`，也不保證 f64 世界幾何逐位元不變。
即使原點只沿 Z 移動，受影響網格的 X、Y 座標也可能重新量化成 f32 值。
未被此操作寫入的無關 f64 資料仍須保留。

如果任務需要更嚴格的 f64 幾何不變條件，須另選符合條件的操作流程。
保留原始失敗、輸入、精度設定及比較結果。
既有來源比較的 1e-6 門檻，不能用來替換另一項更嚴格的檢查。

## 有限平移案例的 f64 指令組合

下列方法只適用於這個範圍：

- 父變換為單位矩陣。
- 部件沒有旋轉，縮放為 `[1,1,1]`，也沒有 delta 或父反向矩陣。
- 網格只有這個部件使用。
- 要保留的子物件也符合這些變換條件。

例如部件沿 Z 平移 0.31 公尺，要將部件原點移到世界 Z=0：

1. 以 `set_mesh_vertices` 將全部受影響局部頂點的 Z 加上原平移量。
2. 以 `set_transform` 將部件的 Z 平移設為 0，保持 f64 變換路徑。
3. 以 `set_transform` 將需要保持世界位置的直接子物件局部 Z 加上原平移量。

把這些指令放在同一批 `scene_apply`，並提供目前的 `expected_revision`。
每個指令仍須留下有效場景。整批成功後才保存。
不要直接改寫母檔來代替正式工具操作。

這是現有正式指令的組合，不是通用 `set_origin` 或 reparent 算子。
它不能直接套用到共享網格、一般父旋轉、非單位縮放或奇異矩陣。
f64 算術也可能捨入，仍須用原先固定的條件比較全部受影響世界幾何。

## 核對世界幾何

父反向矩陣會影響世界變換。
驗證時不能只把父子物件的平移相加。
可分別查詢正式世界資料與物件狀態：

```sh
formora scene inspect --scene PATH --entity ID --world
formora scene inspect --scene PATH --entity ID --object-state
```

核對每個受影響部件及其子項。
另核對保存、實際結束程序、新程序重開及再編輯的結果。
資料檢查、GPU 預覽、外部 Rust consumer 與嵌入式遊戲畫面各有自己的驗收範圍。
