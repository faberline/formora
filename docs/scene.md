# 場景核心

本模組屬於 [0.1 的場景核心工作](https://github.com/faberline/formora/issues/16)。
它不包含渲染、視窗、MCP 或命令列製作介面。
它的資料測試不能代替 macOS 畫面與試玩驗收。

## 資料

`Scene` 是製作與執行共用的場景資料。
目前格式版本是 1。
物件、材質和門使用固定 ID。
ID 可使用英文字母、數字、底線和連字號，最長 128 個位元組。
顯示名稱和註記可使用中文。

座標使用公尺。Z 軸向上。座標系是右手座標系。
旋轉使用四元數，也就是用四個數字表示方向。
四個數字依序是 X、Y、Z、W，且平方和須接近 1。
預設旋轉是 `[0, 0, 0, 1]`。
鏡頭沿本地的負 Z 軸觀看，本地 Y 軸向上。

物件可以是空物件、幾何、鏡頭或燈光。
幾何目前支援方塊與平面。
物件可指定父物件。父物件必須存在，且不能形成循環。
子物件的變換相對於父物件。

材質包含底色、粗糙度及金屬度。
這些資料目前沒有渲染驗收。
門以旋轉控制一個物件。門板可以是鉸鏈物件的子物件。
房間範例使用此方式讓門繞邊緣打開。

## 操作與復原

`Editor::apply` 接收一批指令。
每個指令依序執行，執行後的場景都必須有效。
整批成功時，版本號只增加一次。
任一指令失敗時，場景和復原紀錄都不變。

呼叫者可提供預期版本號。
版本號不同時，操作會失敗，避免 agent 覆寫較新的修改。
`Editor::undo` 復原上一批成功操作。
復原後的版本號仍會增加。
復原紀錄只留在目前程序中，不會隨場景儲存。

目前指令包含建立物件、設定變換、刪除物件、設定材質、
設定鏡頭、建立門、修改開門時間、觸發門、推進時間和新增註記。
刪除仍被引用的物件會失敗。
系統不會默默刪除子物件、門或註記。

## 門的播放

門的進度介於 0 與 1。
0 表示關閉，1 表示打開。
`TriggerDoor` 指定打開或關閉的目標。
`Advance` 依秒數推進進度。
開門時間是從進度 0 到 1 所需的秒數。
中途反轉方向時，會從目前進度繼續。

旋轉採最短方向的正規化線性插值。
這表示中途角速度不一定固定。
修改開門時間時，目前位置不會突然改變。
目前沒有碰撞、門鎖或音效模擬。

## 儲存

`Scene::save` 先驗證場景，再寫入同目錄的暫存檔。
檔案同步完成後，再替換目標檔案。
`Scene::load` 拒絕未知欄位、錯誤格式版本、重複 ID 及無效引用。
數字必須是有限值。
JSON 讀取使用精確的浮點數往返模式，避免重開時改變數值。

目前尚無跨程序寫入鎖。
同一場景不能由多個程序同時寫入。
此限制須在命令列與 MCP 介面工作中處理。

## 檢查

```sh
cargo test --locked --test scene
```

資料流程測試涵蓋房間、門、減慢速度、儲存重開、錯誤回復、
版本衝突、父子循環、重複 ID、無效數字及註記。
