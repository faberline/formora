# 保留有有效角法線的面

原生三角面的面積不能只靠一次浮點叉積判定。
極小座標差異可能在減法中消失，讓結果算成零。
這不代表原生面積在數學上是零。

預覽先計算可用的世界角法線。
即使平面叉積算成零，只要三個角法線都有限且可正規化，就保留三個來源頂點。
位置、順序、材質及角 RGBA 都依原規則投影。
真正退化但有有效角法線的面也保留在頂點流。
這不代表每個面都會在畫面中產生像素。

一般非零面的原計算保持不變。
沒有可用角法線時，仍使用原平面法線回退規則。
世界縮放為零且兩種法線都不可用時，仍不產生預覽頂點。
這個修復不加入面積 epsilon，也不改來源座標、法線、拓撲或原生儲存資料。
它沒有更改 picking 或原生數值算子。

有些場景的 `geometry.vertices` 與 `PreparedScene.vertex_count()` 會增加。
這是原本錯誤略過的來源角點回到預覽流。
原始資產的面數不變。
不要把較舊版本的空頂點流當作正確幾何。

[CPU 回歸](../tests/authored_faces.rs)使用原創二進位分數：
A=(1,1,0)、B=(0,0,0)、C=(2^-60,0,0)。
其精確面積非零，但以 A 為起點的 f64 邊向量叉積算成零。
三個點在 f32 中仍不同。
測試檢查位置、法線、顏色、同 revision 修改、舊快照與恢復。

[外部 GPU 回歸](../tools/renderer-consumer/src/main.rs)使用明確相機變換放大此面。
它必須產生真實非背景像素。
live 與 prepared 的畫素須完全相同，且新資料不能改寫舊快照。
GPU、程序與效能只在 CI 或獨立 consumer 執行。

來源資料始終使用原生 f64 保存。
預覽仍是 f32 投影。
獨立使用端須用固定 commit 驗收全部模型、四視角、角顏色與原有畫面門檻。
此修復不等於整體原生幾何、渲染品質或遊戲效能都通過。
